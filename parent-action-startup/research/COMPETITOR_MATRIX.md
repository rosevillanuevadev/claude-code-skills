# Competitor Forensic Matrix

Do not merely copy feature lists. Test how each product actually behaves.

## Research dimensions

For every competitor, capture:
- company/product name
- website
- headquarters / primary geography
- year founded
- founders and origin story
- target customer
- buyer
- parent vs school-led onboarding
- school adoption required?
- parent app required?
- no-account web flow?
- notices
- read receipt
- acknowledgment
- consent/forms
- document upload
- absence reporting
- excuse letter workflow
- recipient acceptance/rejection
- multi-child experience
- spouse/guardian/delegate support
- action inbox / outstanding items
- original source preserved?
- reminders
- CSV import
- integrations
- pricing
- setup/implementation fees
- free tier/trial
- customer count (source and date)
- funding
- acquisition/exit
- app-store rating/review count
- recurring complaints from 1–3 star reviews
- recurring praise
- setup friction
- sales-led or self-serve
- product bloat / adjacent modules
- probable support burden
- privacy/security claims
- evidence URLs and access dates

## Analysis questions

1. Which products require the school to buy first?
2. Which can a parent use independently?
3. Which support parent→school formal actions without a school account?
4. Which have truly lightweight onboarding?
5. Which products became large suites after starting narrow?
6. Which recurring customer complaints point to a simplicity opportunity?
7. Is there a gap around delegation to a spouse/assistant/caregiver?
8. Is there a gap around preserving the original notice next to the extracted action?
9. Is there a gap around one unified “Needs Action / Waiting / Done” model?
10. Can we offer meaningful value without replacing any school system?

## Evidence standard

Use a table or one file per competitor. Distinguish:
- verified fact
- vendor claim
- user review
- inference
- hypothesis
