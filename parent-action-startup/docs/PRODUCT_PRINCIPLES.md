# Product Principles

## 1. Parent-first, not school-dependent
A parent should be able to start today. School participation improves the workflow but should not be the gate.

## 2. Action, not communication volume
The app is not another inbox. It turns school communication into a clear next action or a clear “nothing required.”

## 3. One job, done well
If a requested feature belongs more naturally in an SIS, LMS, payment system, gradebook, chat app, or family organizer, do not build it by default.

## 4. Original source is preserved
When a notice is summarized or extracted, the original letter/file/message should remain accessible so the parent can verify context.

## 5. Who owns the next step?
Every active item should make ownership obvious: parent, delegate, school, or nobody.

## 6. No installation requirement for recipients
Teacher/school recipients should be able to receive and acknowledge a parent-originated item through a secure web flow without installing an app or creating an account.

## 7. Mobile first
Most parent actions should be completable from a phone in under a minute.

## 8. Minimal data
Collect only what is necessary to complete and track the action.

## 9. No fake certainty from AI
AI extraction is a suggestion. Parent confirms critical fields such as child, due date, action, recipient, and absence dates before sending.

## 10. Small-team maintainability
Avoid a feature or architecture that requires a large support, integration, or implementation team.
