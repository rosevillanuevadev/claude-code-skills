# ADR-0001 — Parent-first, school-compatible

## Status
Accepted as current strategy.

## Context
A school-only SaaS requires procurement, implementation, and institution-wide adoption before the parent receives value. The originating problem is experienced directly by busy parents.

## Decision
Build parent-first. A parent can create/manage actions and send formal absence/excuse records without school onboarding. School participation is progressive rather than mandatory.

## Consequences
Positive:
- faster user validation
- global direct-to-parent reach
- lower initial sales friction
- possible product-led exposure to schools

Negative:
- parent may need some manual data entry
- school acceptance of third-party records varies
- later two-sided workflows require careful identity/permission design
